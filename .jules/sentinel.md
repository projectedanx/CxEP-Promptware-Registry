## 2024-05-24 - [Critical Supply Chain Vulnerability & Command Injection]
**Vulnerability:** Found a reference to a nonexistent GitHub Action (`OrRosenblatt/validate-yaml-action@v1.0.1`) which presents a severe repojacking risk. Additionally, the previous configuration utilized `${{ steps.changed-files.outputs.all_changed_files }}` directly inside a run script, exposing the CI pipeline to command injection.
**Learning:** External actions must be verified for existence, trustworthiness, and maintenance. Directly interpolating untrusted variables within a run script poses a major security hazard.
**Prevention:** Avoid third-party actions when standard tooling (like Python's `check-jsonschema`) suffices. When passing data into shell scripts within a workflow, always bind the context to an environment variable and use the shell's secure variable expansion mechanisms instead of direct interpolation.
## 2024-05-25 - [Medium Severity: Flag Injection via Filenames]
**Vulnerability:** Found a flag injection vulnerability in GitHub actions script that processes filenames provided by `tj-actions/changed-files`. When files begin with a `-`, they might be parsed as flags instead of filenames (e.g. `yamllint -h.yml`), allowing attackers to potentially execute code or leak data. Furthermore, missing `diff_filter: ACMRT` led to executing commands on deleted files, leading to errors.
**Learning:** Any dynamic values controlled by users (like filenames) passed to bash scripts without the end-of-options marker `--` could be misconstrued as flags.
**Prevention:** Always use `--` before dynamic arguments passed to standard unix/linux utilities (e.g., `yamllint -- "$file"`) and configure `diff_filter: ACMRT` for `tj-actions/changed-files` appropriately to handle deleted files gracefully.
## 2024-05-26 - [High Severity: Command Injection via Unsafe Loop Constructs]
**Vulnerability:** Found `for` loop constructs iterating over space-separated arrays inside shell scripts within GitHub Actions (`for file in $CHANGED_FILES; do ... done`). This pattern allows untrusted filenames with spaces or shell characters to cause word splitting or command injection.
**Learning:** Shell `for` loops should never be used on dynamically generated lists of untrusted strings (like filenames from PRs), as they break on spaces and evaluate shell constructs.
**Prevention:** Use a safe delimiter like a comma in `tj-actions/changed-files` output, and pipe the output securely to the target executable using `xargs -d ','` or `xargs -0`. This is both securely bounded and avoids interpreter startup overhead inside the loop.
